# smolvla on Colab T4: prepared, not measured (2026-10-21)

## Status

**No SmolVLA number was measured on the Colab T4 in this session.** The
2x goal is still open for this model. The run is prepared; the GPU is
missing.

## What the run needs

1. A GPU. The Colab T4 assign endpoint answered `Service Unavailable`
   on every attempt of the session (see
   `docs/perf/minimind-omni-2026-10-20.md`).
2. The `lerobot` package. The latest release is 0.6.1, and its
   `smolvla` extra pulls `transformers>=5.4.0,<5.6.0`. The SmolVLM
   measurement ran on transformers 5.15.0, so the two runs use
   different transformers versions. The install was verified on the
   Colab CPU session (2026-10-21):

   ```
   lerobot 0.6.1
   transformers 5.5.4
   torch 2.11.0+cpu
   ```

   The resolver picked transformers 5.5.4, inside the range the extra
   pins.

   The Colab image already carries transformers 5.15.0, so the install
   leaves a mixed package directory and the import fails with
   `ImportError: cannot import name 'lazy_import_paged_flash_attention'
   from 'transformers.modeling_flash_attention_utils'`. The repair is
   to delete the `transformers` directory in `site-packages` and
   install the pinned version again
   (`.scratch/colab/fix_transformers.py`). Run the SmolVLA
   measurement on its own session: the downgrade breaks the 5.15.0
   environment that the SmolVLM measurement used.

   The install also pulls `diffusers` and `torchao`, and the resolved
   pair does not match. The import of
   `lerobot.policies.smolvla.modeling_smolvla` runs
   `lerobot.policies.__init__`, which imports the groot configuration,
   which imports the groot package, which imports `diffusers`:

   ```
   RuntimeError: Failed to import diffusers.models.modeling_utils ...
   cannot import name 'FqnToConfig' from 'torchao.quantization'
   ```

   The SmolVLA path never uses torchao, and diffusers treats it as an
   optional dependency, so removing the package clears the import
   (`.scratch/colab/remove_torchao.py`).

   The next import error is the one that the `dataset` extra of
   lerobot fixes:

   ```
   ImportError: 'av' is required but not installed. Install it with:
   pip install 'lerobot[dataset]'
   ```

   `lerobot.datasets` requires PyAV, and the import chain reaches it
   through the policy factory. The project now declares `av` in the
   `smolvla` extra of `pyproject.toml`, so a fresh install works.

   `colab exec` runs its script in the kernel process, and the kernel
   keeps the half-imported `transformers` module from the first failed
   import. A later run in the same kernel then fails with the same
   `ImportError` even though the installed package is fine. Run the
   measurement in a fresh session, or in a subprocess.
3. The `HuggingFaceVLA/smolvla_libero` checkpoint in the HF cache. The
   bench path passes `allow_hf_download=False`, so the weights have to
   be pre-downloaded (`.scratch/colab/fetch_smolvla.py`).

## API check against lerobot 0.6.1

The repo drives the lerobot internals (see
`docs/dev/nanovllm-omni-smolvla-arflow-migration.md`), so the installed
version has to match the calls. Read against the 0.6.1 sources, then
confirmed against the installed package (signatures printed with
`inspect.signature`):

| repo call | lerobot 0.6.1 |
|---|---|
| `from lerobot.policies.smolvla.modeling_smolvla import SmolVLAPolicy` | the class lives in that file (`modeling_smolvla.py`, line 142) |
| `SmolVLAPolicy.from_pretrained(path, strict=False, local_files_only=True)` | `from_pretrained(pretrained_name_or_path, *, ..., local_files_only=False, ..., strict=False, **kwargs)` — both keywords exist |
| `policy.model.sample_noise(shape, device)` | `VLAFlowMatching.sample_noise(self, shape, device)`; `policy.model` is a `VLAFlowMatching` instance |
| `policy.model.denoise_step(x_t=..., prefix_pad_masks=..., past_key_values=..., timestep=...)` | `VLAFlowMatching.denoise_step(self, prefix_pad_masks, past_key_values, x_t, timestep)` — same keyword names |

The action stage also reads `policy.config.chunk_size`,
`policy.config.max_action_dim`, `policy.config.action_feature`, and
`policy.config.num_steps`.

## The policy loads (measured 2026-10-21)

The checkpoint was fetched on the Colab VM and loaded with the call
that `nanovllm_omni/models/smolvla/policy.py` makes. The 489 weight
tensors loaded, and every field that the action stage reads is present:

```
policy: SmolVLAPolicy
chunk_size: 50
max_action_dim: 32
num_steps: 10
action_feature: PolicyFeature(type=ACTION, shape=(7,))
model: VLAFlowMatching
has sample_noise: True
has denoise_step: True
sample_noise: (1, 50, 32) torch.float32
```

The checkpoint ships 8 files: `config.json`, `model.safetensors`, the
pre/postprocessor JSON files, and their two safetensors.

The 7-dim action feature matches the synthetic observation that
`tests/test_smoke_gpu_e2e.py` builds (a 3x224x224 image plus a 7-dim
state), so the bench input has the shape the checkpoint expects.


## The measurement

The bench path is the one in `tests/test_smoke_gpu_e2e.py`: a synthetic
observation (a 3x224x224 byte image plus a 7-dim state) through
`PipelineRunner.run_payload`. The script
`.scratch/colab/s_smolvla.py` runs one warmup plus five timed runs and
prints the median wall time and the peak VRAM. The environment setup is
`.scratch/colab/s_deps_smolvla.py`.
