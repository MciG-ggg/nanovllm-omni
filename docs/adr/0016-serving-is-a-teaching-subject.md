# ADR 0016: serving 本身就是教学对象

- Status: Accepted
- Date: 2026-11-09
- 关联: ADR 0007（minimind 吞吐）、0010（并发不是杠杆）、0012（批处理）、
  0013（backend 接缝）、0014（双轨目标）、0015（MLX 要 varlen）

## 问题

`AGENTS.md` 开头的定位是：

> `nanovllm-omni` 是一个**教学项目**：目标是让人读懂 omni（文本→音频）推理链路是怎么跑起来的，
> 并在一张 4 GB 的 RTX 3050 上真的跑通。它不是生产推理引擎，不追求吞吐、不追求覆盖所有模型。
> 一切取舍的判据只有一条：**代码是否更容易读懂**。

这段话有三个问题：

1. **硬件目标已经失效**：4 GB 显存限制已取消，ADR 0014 定了双轨（3050 + Mac）。
2. **"教学对象"被写窄了**：教学目标是"omni 推理链路"，但这个仓库最有价值的产出
   其实是 serving 侧的结论——ADR 0010「并发不是杠杆」（线程并发实测 1.8× 恶化并崩一个请求）、
   ADR 0012「bs=8 是净亏」（+32%）、ADR 0007「talker 成本不在 O(n²)」。
   **这些结论只有真的去实现 serving 才拿得到**，而它们恰恰是文档里最有信息量的部分。
3. **"不追求吞吐"和 ADR 0014/0015 冲突**：那两条要求两条轨道都出性能结论。

## 决定

**serving 本身就是教学对象。** 定位改写成两句话：

> `nanovllm-omni` 是 vLLM-Omni 的教学版复刻。教学对象是**整条 omni 推理链路**，
> 从 stage 队列、调度、paged KV 到 batch 形状与吞吐——serving 不是附属功能，是教材本身。
> 取舍的判据是：代码是否更容易读懂，以及每条性能结论是否有实测支撑。

具体口径变化：

| 原口径 | 新口径 |
|---|---|
| 硬件目标：4 GB RTX 3050 | 至少在一台 Mac 上能跑（ADR 0014 双轨） |
| 不追求吞吐 | **不追求没有实测支撑的吞吐**；有 profile 支撑的优化照做（ADR 0014/0015 要求出性能结论） |
| 只讲 omni 推理链路 | 讲整条链路，含调度与 batch 形状 |
| perf 文档是副产品 | perf 文档是教学材料（ADR 0007/0012 已经是这个形态） |

## 后果

- **`AGENTS.md` 的定位段要改写**，否则后续 agent 会被"4 GB"和"不追求吞吐"卡住——
  这和 2026-11-08 已经提过一次的提醒是同一件事。
- **"不做未测量的性能优化"这条规矩不变**，但它的含义要精确：
  没有 profile 数据支撑的优化不写；有 profile 支撑的优化不但可以做，还要把
  优化前后的对比写进同一份结果文档（AGENTS.md「文档同步」段已经这么要求）。
- **教学价值要显式承载体**。新加的 serving 相关代码，注释和文档要回答
  "这一段为什么长这样"，而不只是"这一段做了什么"——
  ADR 0010 那种"并发注定无效"的推理过程，就是教材的形态。
- **性能结论要能跨人复现**。ADR 0014 已定"按机器分开记，不跨机相减"，
  这条也要写进 perf 文档的模板。

## 边界

- 本 ADR **不**放宽"不加假想的 corner case""抽象只在第二个真实使用者时出现"这类规矩。
  教学项目对代码可读性的要求不因为 serving 而降低。
- 本 ADR **不**意味着要覆盖更多模型族。覆盖面的取舍标准是"这个族能教什么"，
  不是"这个族能不能跑"。
- 本 ADR **不**改变 parity 标准（ADR 0011）与批次一致性口径（ADR 0012 的
  "跨 batch size 不承诺逐位等价"）。
