## Initial observation

- **SmolVLM-500M is launch-bound, not compute-bound.** GPU only speeds up short-prompt case (3x); medium/long barely improve over CPU (1.2-1.4x). The 500M LM is small enough that GPU launch overhead matches per-token compute cost.
- **AR decode is the bottleneck.** 64 max_new_tokens × 64 LM forwards per generation = 64 sequential small kernels. With Kineto profiling on each kernel launch has measurable overhead.
- **VRAM ~1 GB constant** across all 3 inputs -- model footprint dominates; KV cache + intermediates are small.
- **GPU util ~15% during bench** (nvidia-smi polled externally) -- confirms launch-bound, not compute-bound.

## Bottleneck hypothesis (preliminary)

SmolVLM-500M on RTX 3050 with AR decode = **launch-bound**. Optimization levers worth testing in Phase 2:

1. **CUDA Graph capture** for the decode step. Single forward becomes one launch instead of ~30 kernel launches.
2. **Static KV cache** to avoid reallocation per token.
3. **Reduce sync points** -- `torch.cuda.synchronize()` per timed forward is necessary for accurate timing, but the bench could amortize sync over N forwards.

## Phase 2 plan

1. Add NVTX `:tokenize` / `:vlm-prefill` / `:vlm-decode` markers around the 3 calls in `_infer_one`. Re-profile to split 123 / 3905 / 3969 ms into stages.
2. Design cell matrix targeting **decode step** (the dominant cost):
   - Cell A: baseline (current)
   - Cell B: CUDA Graph capture on (prefill + decode)
   - Cell C: CUDA Graph capture on (decode only; prefill separate)
   - Cell D: CUDA Graph + static KV cache
3. Colab T4 ncu SOL for the top-3 decode-step kernels.
